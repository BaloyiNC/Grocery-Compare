# Grocery Compare

Compares Checkers, Pick n Pay, Spar and Woolworths so people find the cheapest store, or mix of stores, for a whole shopping list. Plain HTML, CSS and JavaScript, no framework.

## Run it

Requires Node.js 18 or newer. From the project folder:

```sh
npm ci
npm run build-data
npm test
```

Then open `index.html` in a browser. To check the phone layout, press F12 in Chrome and use the device toolbar. The generated `data/data.js` is included so the app also works from a direct local file open.

## Folder guide
| Path | Purpose |
| --- | --- |
| `index.html`, `style.css`, `script.js` | The app (see `Planning Docs/grocery-compare-ux-ui.md`) |
| `data/products.csv` | **The file you edit.** One row per currently listed catalogue offer, including end date and source URL |
| `data/config.json` | Stores, colors, loyalty card names, categories, data mode, and the `updated` date |
| `data/data.js` | Generated by `tools/import.js`. Do not edit by hand |
| `tools/import.js`, `tools/validate.js` | Import and check the data |
| `tests/app.test.js` | Behaviour tests (add, quantities, focus, saved state, loyalty totals, specials, branches, freshness, large catalogue). Run `npm ci` then `npm test` |
| `docs/` | Price source policy, data format, maintenance, data changelog, backlog and QA checklist |
| `.github/workflows/pages.yml` | Builds, validates, tests and deploys to GitHub Pages when changes are pushed to `main` |

## Current price coverage

`data/products.csv` now contains 34 current offers listed by My Catalogue, captured on 2026-11-01, with source links and offer end dates (currently through 2026-11-08). These are **offer prices, not regular shelf prices**. `Size not stated` means the source listing did not provide a size; those rows must not be treated as equivalent products across stores.

The source warns that specials may not apply at all local stores. Gauteng branch-level availability has not been verified. A blank store row means no offer was recorded for that retailer, not that the item is unavailable there. This dataset therefore does not support a reliable full-basket price comparison yet. Regular prices, loyalty prices, and matched product comparisons should only be added when verified.

## Refreshing catalogue offers
1. Review My Catalogue for current offers and confirm each offer's product, price, end date and any Gauteng/branch restrictions.
2. Replace or update the offer rows in `data/products.csv`, retaining each source URL. Do not infer missing sizes or regular prices.
3. Set `"updated"` in `data/config.json` to the capture date (YYYY-MM-DD).
3. Run `npm run build-data` (imports, then validates; needs Node 18+).
4. Add an entry to `docs/data-changelog.md`.
5. Commit and push. The app warns users when data is older than 14 days.

Full steps, including how to roll back a bad refresh, are in `docs/maintenance.md`.

## Recommended next steps

1. Before the offers expire, refresh the list and verify the terms, offer dates, and Gauteng/branch applicability for each listing.
2. Add regular shelf prices and exact-size cross-retailer matches only when those details can be verified; the current offer listings alone do not enable a complete basket comparison.
3. Configure the repository's **Settings → Pages → Build and deployment → GitHub Actions**, then push to `main` to publish. The workflow runs the data build and automated tests before deployment.
4. Complete the postponed manual checks in `docs/qa-checklist.md` on real devices, browsers, keyboard and screen reader, offline, storage and location permissions.
5. Decide the LICENSE and analytics policy. Add verified Gauteng branch availability if that data becomes available.

Do not announce a production launch or treat the app's displayed prices as current until the source, permissions, data and manual checks are complete.
